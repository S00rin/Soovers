# استقرار SooVers از Git

نسخهٔ 0.4 یک وب‌اپ استاتیک است. برای نمایش دمو به دیتابیس، کلید API، Splunk یا حساب ابری نیاز ندارد. نصب سرور شرکت در این جلسه انجام نشده؛ مقصد از طرف کاربر روی سرور خودش اجرا می‌شود.

## روش اول: خروجی ساخته‌شده

بستهٔ `releases/SooVers_Demo_0.4.0.zip` را از همین مخزن بگیر. checksum کنار ZIP است. پوشهٔ `site` را با وب‌سرور موجود سرو کن یا با Node:

```bash
node run.mjs
```

پورت پیش‌فرض 8080 و اتصال پیش‌فرض فقط روی loopback است. برای سرو مستقیم داخل شبکهٔ آزمایشی:

```bash
HOST=0.0.0.0 PORT=8080 node run.mjs
```

برای دسترسی اینترنتی از Reverse proxy و HTTPS فعلی سرور استفاده کن. `/healthz` روی سرور Node باید JSON شامل `status: ok` بدهد.

## روش دوم: ساخت از Git

```bash
git clone https://github.com/Ali-MJI/SooVers.git
cd SooVers
git checkout v0.4.0
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm build:selfhost
pnpm start
```

Node.js نسخهٔ 24 پیشنهاد می‌شود. `local-dist` خروجی قابل سرو است. `pnpm start` سرور توسعهٔ Wrangler نیست؛ فقط فایل‌های همین پوشه را سرو می‌کند.

## Docker

```bash
docker compose up -d --build
curl --fail http://127.0.0.1:8080/healthz
docker compose logs --tail=40 soovers
```

Compose سرویس را فقط به `127.0.0.1:8080` سرور متصل می‌کند. پورت را با سرویس‌های موجود تطبیق بده. فایل `deploy/nginx.conf` نمونهٔ location برای Reverse proxy موجود است؛ دامنه و TLS باید در تنظیم فعلی شرکت قرار بگیرند. فایل `deploy/soovers.service` جایگزین Docker برای systemd است؛ مسیر Node، کاربر سرویس و مسیر پروژه را مطابق سرور تنظیم کن.

## نصب زیر مسیر

دارایی‌های Build و فونت‌ها نسبی‌اند. می‌توان خروجی را زیر `/soovers/` سرو کرد. در Nginx پیشوند را با `proxy_pass http://127.0.0.1:8080/;` حذف کن، یا Node را با `BASE_PATH=/soovers` اجرا کن. این دو روش را هم‌زمان استفاده نکن. مسیر ریشه باید به `/soovers/` با اسلش پایانی هدایت شود.

## تأیید پس از استقرار

۱. پاسخ سالم `/healthz` و نبود 404 برای JS، CSS و فونت‌ها.
۲. برج، پذیرش، کارت دانشجو و آزمون ۸ سؤال.
۳. ورود به کلاس از مسیر و دیدن مدل بازشوندهٔ تجهیزات.
۴. تکمیل پرونده از پایانه و بازکردن همان پرونده در SOC.
۵. آزمون روی مرورگر و هدست هدف؛ تست Headless جای تست هدست را نمی‌گیرد.

## بازگشت

برای هر نسخه یک پوشه یا تگ تصویر مستقل نگه دار. قبل از تعویض، نسخهٔ تازه را روی پورت دیگر بررسی کن. برای بازگشت، Reverse proxy یا لینک `current` را به آخرین نسخهٔ آزموده‌شده برگردان. دادهٔ مسیر کاربر در localStorage مرورگر با کلید `soovers-learning-v1` است و در این نسخه مهاجرت پایگاه داده وجود ندارد. در استقرار بعدی کلید قدیمی دفترها (`soorin-notebooks-v1`) حفظ شده است.

کارت‌های دمو احراز هویت نیستند. اگر مقصد فقط برای ارائهٔ شرکت است، محدودیت دسترسی را روی Reverse proxy موجود اعمال کن. تولید محتوا، آزمون و امتیاز این نسخه مرز امنیتی سمت سرور ندارند.

## شبکهٔ سازمانی هنگام Build

Dockerfile از گواهی‌های پیش‌فرض TLS استفاده می‌کند. اگر شبکهٔ سازمان CA اختصاصی دارد، گواهی عمومی مورد اعتماد را با BuildKit secret وارد کن: `docker build --secret id=build_ca,src=/path/to/company-ca.pem -t soovers:0.4.0 .`. این گواهی فقط هنگام نصب استفاده می‌شود و در تصویر نهایی ذخیره نمی‌شود. Proxy و DNS باید طبق شبکهٔ همان سرور تنظیم شوند؛ بررسی TLS را غیرفعال نکن.
